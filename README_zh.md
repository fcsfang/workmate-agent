## 一件长期的事，如何被持续推进

假设你准备在周五做一次读书分享。你只需要告诉 Workmate：

> 我需要读完剩余章节、整理分享提纲，再做一份简单的演示文稿。现在先读书和整理笔记。

接下来发生的事情，不会停留在一次回复里：

1. 计划被整理为一个主任务和三个子任务，当前行动明确为阅读与笔记。
2. 你离开聊天页面开始执行，任务状态和下一步仍被持续保存。
3. 你回来汇报“读完第三章，还剩最后两章”，原任务会直接更新，而不是重新开始一段对话。
4. 当任务长时间没有推进、承诺临近，或屏幕活动连续离开当前目标时，Workmate 会主动把主线带回来。
5. 一段时间后，这些进展会沉淀为可回顾的任务轨迹、目标、偏好和行为模式。

![任务闭环：对话、当前计划、子任务与监督反馈](docs/assets/task-lifecycle.png)

*一句计划，逐渐成为一条能够被记住、更新、监督和完成的行动主线。*

## 让目标一直在场

长期目标最容易消失在日常事务里。不是正式放弃，而是今天被一条消息打断，明天换了一件更急的事，几天后已经说不清上次进行到了哪里。

Workmate 会持续保存当前主线：正在推进什么、已经完成什么、卡在哪里、下一步是什么。刷新页面、重新启动应用或隔一段时间回来，事情仍然从原来的位置继续。

它记得的不只是你说过什么，更重要的是：

- 哪一件事现在最重要；
- 大任务由哪些子任务组成；
- 当前进度停在什么位置；
- 哪些承诺还没有关闭；
- 下一次行动应该从哪里接上。

目标因此不再依赖用户反复回忆和重新规划，而是始终以一个可继续执行的状态留在工作台上。

## 看见你此刻正在做什么

这是 Workmate 最具辨识度的能力。

视觉主动监督不是简单记录用户打开了哪个应用，而是**带着当前目标理解屏幕中的实际内容**。同样是浏览器，它可能承载任务资料，也可能已经把注意力带向无关内容；同样是阅读软件，它也可能正是当前工作的核心现场。

Workmate 会把三类信息放在一起理解：

- **当前目标**：用户此刻真正准备推进什么；
- **屏幕语义**：画面中的内容正在发生什么；
- **近期轨迹**：这是一次短暂切换，还是注意力已经连续离开主线。

视觉模型据此决定保持安静、给出同行反馈，或直接提醒用户回到当前任务。用户也可以主动点击“观察屏幕”，立即获得一次结合任务上下文的视觉反馈。

这让监督真正发生在行动过程中：不用要求用户停下来描述自己是否分心，Agent 会先理解工作现场，再选择下一步反应。

![视觉监督：理解当前屏幕并给出陪伴反馈](docs/assets/vision-supervision.gif)

*用户主动触发观察后，视觉模型会理解屏幕活动与当前目标的关系。*

![视觉监督详情：监督消息与当前任务保持关联](docs/assets/vision-supervision.png)

*监督消息带着当前任务上下文进入对话。临时截图在分析完成后从本地删除，视觉反馈也不会写入长期情节记忆。*

## 在目标快要掉出视野时主动出现

Workmate 不需要等用户想起来再打开聊天窗口。只要本地服务保持运行，它就会在后台持续关注行动状态：

- 专注会话是否已经结束；
- 当前任务是否长时间没有更新；
- 已经做出的承诺是否正在临近；
- 屏幕活动是否连续偏离当前目标。

这些信号会形成可追踪的监督事件。用户可以确认、稍后处理、静音、关闭或标记完成，Workmate 则继续知道这件事有没有被处理，而不是反复发送同一条通知。

主动监督的价值，是在目标被新的事务彻底覆盖之前，让它重新回到用户面前。

关闭启动 Workmate 的终端后，任务和记忆仍会保存在本机，后台检查则会暂停，直到下一次启动。

## 让零散努力沉淀为长期积累

今天读到哪一章、项目在哪一步受阻、什么样的提醒最有效，这些信息不应该随着一次对话结束而消失。

Workmate 会把不同时间尺度的信息分别保存：

- 当前任务、承诺和专注状态，构成此刻可信的行动现场；
- 稳定目标、沟通偏好和重复行为模式，逐渐形成长期认知；
- 过去的对话与进展，在真正相关时重新进入上下文；
- 阶段总结和反思，为后续复盘留下依据。

使用时间越长，Workmate 越能沿着已经形成的主线继续支持用户，而不是每次都从一张白纸开始。

## 适合这些场景

- **长期项目推进**：持续记录阶段目标、当前阻塞和下一步，避免项目在日常事务中失去主线。
- **学习与阅读计划**：跟踪章节、笔记、提纲和复习进度，把较大的学习目标变成连续行动。
- **深度工作与注意力管理**：开始专注会话，让 Agent 在实际工作过程中持续关注目标。
- **个人承诺与自我管理**：保留已经做出的承诺，在临近或停滞时重新带回视野。

## 数据与隐私

Workmate Agent 面向本地单用户使用。任务、对话、用户画像、长期认知和向量索引默认保存在本机，不会提交到 Git。

模型推理仍可能使用你配置的外部 API。普通对话会把必要上下文发送给语言模型；启用视觉监督后，临时屏幕截图会发送给视觉模型分析，并在调用结束后从本地删除。请根据所选服务商的隐私政策决定是否启用相关能力。

你可以随时清除全部本地记忆：

```bash
# 先在运行终端按 Ctrl+C 停止服务
./scripts/clear_memory.sh
```

脚本会删除对话、任务、画像、长期认知、屏幕观察、向量索引和历史备份，但不会删除 `.env`、项目代码和通用方法论知识库。

## 快速开始

### 环境要求

- Python 3.12+
- 推荐使用 Conda，也支持自动创建本地 `.venv`

### 安装与配置

```bash
git clone https://github.com/fcsfang/workmate-agent.git
cd workmate-agent
cp .env.example .env
```

在 `.env` 中填写 OpenAI 兼容模型配置：

```env
LLM_MODEL_ID=moonshotai/kimi-k2.6:free
LLM_API_KEY=your-api-key-here
LLM_BASE_URL=https://openrouter.ai/api/v1
```

### 启动

```bash
./run.sh
```

启动脚本会检查运行环境、安装依赖、启动 FastAPI 服务并自动打开浏览器。

- Web 页面：`http://127.0.0.1:7860`
- OpenAPI 文档：`http://127.0.0.1:7860/docs`
- 自定义端口：`WORKMATE_PORT=7861 ./run.sh`
- 停止服务：在运行终端按 `Ctrl+C`

首次启动时，Workmate 会从一个干净的工作台开始，等待用户说出准备推进的事情：

![Workmate Agent 初始化界面](docs/assets/init.png)

视觉监督、系统通知和讯飞 TTS 均为可选能力，可以在 `.env` 和页面设置中单独开启。

## 为什么它是一个 Agent

Workmate Agent 不只是把输入转发给大模型。每轮交互都会结合当前状态和相关记忆，判断是否需要调用内部工具，再将结果写回任务、承诺和记忆系统。后台调度器还会在没有新消息时主动检查监督条件。

产品体验背后的主要能力包括：

- 可观察的 Agent 执行链路；
- 分层长期记忆与历史检索；
- 用于内部状态管理的工具调用；
- 主动监督事件生命周期；
- 多模态屏幕理解；
- FastAPI、OpenAPI 与自动化评估。

这些工程细节不会占据日常界面，需要深入了解时可以查看架构文档。

## 项目边界

Workmate Agent 当前是一个本地优先、单用户的个人生产力 Agent。它不会替用户完成具体工作；它更关心事情现在进行到了哪里、用户是否仍在主线上，以及怎样让一个长期目标持续向前。
