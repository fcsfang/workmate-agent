# Workmate Agent Architecture Walkthrough

This document is the interview-facing walkthrough for Workmate Agent. It is meant to help a reviewer understand the project in a few minutes, then inspect the running demo, OpenAPI schema, and eval report with a clear mental model.

## One-line Positioning

Workmate Agent is a local-first productivity agent with explicit runtime orchestration, hybrid memory RAG, schema-driven internal tools, multimodal screen supervision, observable traces, and reproducible evaluation.

## What To Show First

1. Run `python scripts/reset_demo_data.py`, then `./run.sh`.
2. Open `http://127.0.0.1:7860` and show the demo task, memory, supervision events, and model context panel.
3. Open `http://127.0.0.1:7860/docs` and show typed FastAPI contracts.
4. Open the eval report generated by `python evals/run_eval.py --report-dir /tmp/workmate-eval-reports` when validation is allowed.

## System Architecture

```mermaid
flowchart LR
    User["User"] --> Web["Web UI<br/>web/index.html"]
    Web --> API["FastAPI API<br/>src/web.py"]
    API --> Runtime["Agent Runtime<br/>agent/runtime.py"]
    Runtime --> LLM["LLM Provider<br/>src/LLMClient.py"]
    Runtime --> Tools["Tool Executor<br/>tools/*"]
    Runtime --> Memory["Memory Manager<br/>memory/manager.py"]
    Memory --> State["Authoritative State<br/>tasks + commitments + focus"]
    Memory --> Knowledge["Layered Knowledge<br/>memory/data/knowledge/*.md"]
    Memory --> RAG["Episodic Memory RAG<br/>memory/search.py + memory/retriever.py"]
    Memory --> Supervision["Supervision Loop<br/>memory/supervision_events.py"]
    Supervision --> Vision["Vision Model<br/>screen observation"]
    Runtime --> Trace["Observability Trace<br/>turn_trace + provider trace"]
    API --> OpenAPI["OpenAPI Docs<br/>/docs"]
```

Key point: the project is not only a chat wrapper. The runtime coordinates memory retrieval, tool planning, state updates, supervision events, and trace generation around every turn.

## Agent Loop

```mermaid
sequenceDiagram
    participant U as User
    participant API as FastAPI
    participant R as AgentRuntime
    participant M as MemoryManager
    participant T as ToolExecutor
    participant L as LLM

    U->>API: POST /api/chat or /api/chat/stream
    API->>R: invoke / invoke_stream
    R->>M: build context messages
    M->>M: retrieve memory + plan context
    R->>T: plan and execute internal tools
    T-->>R: observations + audit records
    R->>L: generate response
    L-->>R: assistant text
    R->>M: process turn and update derived memory
    R-->>API: response + tool trace + observability
    API-->>U: UI update / SSE done event
```

What to say: each turn produces a visible execution trace. Tool decisions, RAG decisions, provider calls, and memory writeback are observable instead of hidden inside a single API call.

## Hierarchical Memory and Episodic RAG

```mermaid
flowchart TD
    Query["Current prompt"] --> Planner["Context Planner"]
    Planner --> State["Direct state read<br/>tasks, commitments, focus"]
    Planner --> Knowledge["Layered Markdown<br/>user, goals, preferences, patterns, insights"]
    Planner --> Filter["Episodic metadata filters<br/>type, status, task, salience, time"]
    Filter --> Index["Retrieval Index<br/>JSON or ChromaDB"]
    Index --> Hybrid["Hybrid scoring"]
    Hybrid --> Keyword["Keyword score"]
    Hybrid --> Recency["Recency score"]
    Hybrid --> Salience["Salience score"]
    Hybrid --> Vector["Vector similarity"]
    Hybrid --> TaskRel["Task relevance"]
    Keyword --> Rank["Rank + optional rerank hook"]
    Recency --> Rank
    Salience --> Rank
    Vector --> Rank
    TaskRel --> Rank
    State --> Context["Composed model context"]
    Knowledge --> Context
    Rank --> Context["Historical context with source attribution"]
    Context --> Trace["RAG explainability in observability panel"]
```

What to say: current execution state is never guessed through vector search. Stable cognition is readable Markdown, while RAG is reserved for historical episodes and remains explainable through metadata, attribution, score breakdown, and optional vector search.

## Tool Calling Layer

```mermaid
flowchart LR
    Prompt["User prompt"] --> Planner["Tool planner"]
    Planner --> Registry["Tool registry<br/>schemas + permissions"]
    Registry --> ReadTools["Read tools<br/>search, task state, preferences"]
    Registry --> WriteTools["Write tools<br/>task, focus, memory, supervision prefs"]
    WriteTools --> Audit["Audit record<br/>side effects + input/output keys"]
    ReadTools --> Trace["Tool trace"]
    Audit --> Trace
    Trace --> Response["Final response + observability"]
```

What to say: tools are used for internal state management rather than arbitrary external actions. This keeps the project focused and auditable while still demonstrating schema-driven tool use.

## Proactive Supervision Loop

```mermaid
stateDiagram-v2
    [*] --> detected: scheduler detects event
    detected --> notified: background/page notification sent
    detected --> acknowledged: user acknowledges
    detected --> snoozed: user delays
    detected --> muted: user mutes
    detected --> resolved: user marks done or condition disappears
    detected --> dismissed: user closes
    notified --> acknowledged
    notified --> snoozed
    notified --> resolved
    snoozed --> detected: snooze expires
    muted --> detected: mute expires
    acknowledged --> resolved
    resolved --> [*]
    dismissed --> [*]
```

What to say: supervision is a state machine with transition history and reasons. Screen observations stay lightweight: Vision reminders are visible as transient messages but do not pollute long-term memory.

## 3-5 Minute Demo Script

### 0:00-0:40 Setup

Run:

```bash
python scripts/reset_demo_data.py
./run.sh
```

Say: "This resets local ignored data into a reproducible demo state, then starts the local-first agent. Private `.env` and runtime memory are not committed."

### 0:40-1:30 Product Surface

Open `http://127.0.0.1:7860`.

Show:

- Current task and subtasks.
- Memory panel and RAG/debug context.
- Supervision events with status and transition reasons.
- Transient supervision message in the conversation.

Say: "This is a productivity agent for focus and self-supervision, but the engineering focus is the full agent loop behind it."

### 1:30-2:20 Agent Runtime And Tools

Send a short message such as:

```text
我继续准备 Workmate Agent 的面试 demo，先检查一键启动和 OpenAPI。
```

Show:

- Streamed response.
- Tool trace / planner information.
- Observability summary.

Say: "The agent can plan internal state tool calls and every call includes schema, read/write mode, side effects, and failure recovery hints."

### 2:20-3:10 Memory RAG

Open the model context panel.

Show:

- Retrieval plan.
- Score breakdown.
- Source attribution.
- Injected context reason.

Say: "The memory system combines keyword, recency, salience, vector similarity, and task relevance, then reports why each memory entered the context."

### 3:10-4:00 Supervision

Show `SUPERVISION EVENTS`.

Click `ACK`, `SNOOZE`, `DISMISS`, or explain these actions if not modifying demo state.

Say: "Proactive supervision is not a repeated notification loop. It is a lifecycle state machine with transitions, feedback stats, adaptive strategy explanations, and scheduler boundaries."

### 4:00-5:00 Engineering Evidence

Open:

```text
http://127.0.0.1:7860/docs
```

Optionally open the eval report after running evals when validation is allowed.

Say: "The project exposes typed OpenAPI contracts and has reproducible eval categories for intent, memory recall, tool calling, supervision lifecycle, observability, and API schema smoke checks."
